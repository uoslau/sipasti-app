# Taste
- Writes prompts in Indonesian and expects replies in Indonesian (match the user's language). Confidence: 0.65
- Cares about UI aesthetics: repeatedly asks for views to be made attractive ("lebih menarik", "dashboard menarik"), expecting visual polish, hierarchy, and better component states rather than just functional pages. Confidence: 0.65
- Reviews the rendered UI himself and reports concrete visual imbalances (e.g. "sisi kanan terasa kosong karena data lebih padat di sebelah kiri"), expecting the layout to use the full horizontal width — content spread across aligned columns/lanes rather than clustered on one side — and asking for it to be made "lebih presisi". Confidence: 0.55
- Wants dashboards/landing views to surface genuinely useful, decision-relevant data ("data-data yang berguna ketika user melihatnya") — not decorative filler. Confidence: 0.5
- Expects correct, semantically-clean routing (e.g. app must route to the dashboard and redirect users there after login), flagging route fixes as part of the task. Confidence: 0.4
- Explicitly invites proactive suggestions beyond the literal ask ("atau kamu ada saran lain yang tidak saya pikirkan?") and expects the agent to flag adjacent improvements/issues it notices. Confidence: 0.6
- Prefers incremental, narrowly-scoped fixes over broad batches: when given a prioritized list of issues, picks one ("...saja terlebih dahulu") and expects the agent to address only that before moving on. Confidence: 0.55
- Delegates execution with terse instructions (e.g. replying only "continue") and expects the agent to drive multi-step work to completion — plan, implement, wire up, and verify — without pausing for confirmation. Confidence: 0.45
- Handles environment/host-level concerns himself rather than having the agent touch them: keeps manual database backups (SQL dump files) and swaps the database by dropping it and importing a new dump himself (rather than having the agent run migrations/seeders to rebuild), and expects the agent to leave machine/system settings alone. Confidence: 0.5
- After he replaces the underlying database, expects the agent to reconcile the app to the new data before considering the task done: detect what schema (columns/tables) is missing versus what the features rely on, apply only the additive changes needed, and verify the app still works against the new data without overwriting it. Confidence: 0.45
- When a feature is temporary/experimental, wants it built fully isolated — self-contained model/controller/view/routes/assets that don't touch the existing app — so it can be deleted cleanly later, and expects any unavoidable insertions into shared files to be clearly marked. Confidence: 0.6
- Judges changes by the rendered result and is willing to throw a new implementation away: if a redesign doesn't feel better than what came before, he says so plainly ("ternyata yang sebelumnya lebih baik, kembalikan saja") and expects a clean revert to the earlier version rather than more iteration on the new one. Confidence: 0.45
- Sets explicit access rules for views instead of leaving them open: expects visibility to be gated by user role/team membership (e.g. admin users plus members of a specific tim kerja) and the sidebar entry to follow the same rule. Confidence: 0.45
- Calls out real-world data scale in requests (e.g. Excel imports of "ribuan baris") and expects the implementation to actually handle that volume (chunked reads, bulk writes) rather than only the happy path. Confidence: 0.5
- Wants filter controls that are composable rather than one-at-a-time: several field filters that stack (AND) to narrow results — but has since moved past independent filters to a cascading hierarchy, where each filter's options are limited to values that actually exist under the choices made above it (pick Kecamatan, then Level 4 lists only that kecamatan's desa, then Level 5, then Pencacah), instead of letting him pick impossible combinations. Confidence: 0.6
- Expects filter fields ordered from broadest to most specific scope, and states explicitly which field must come last (e.g. "saya ingin pencacah adalah filter terakhir"). Confidence: 0.5
- Prefers picking filter values from a dropdown populated with the unique values that actually exist in the data, over free-text typing/autocomplete ("sehingga user tidak perlu mengetikkannya") — accepts exact-value matching in exchange for zero typing. Confidence: 0.6
- Prioritizes compact, space-efficient UI: wants bulky control sets (e.g. the full filter panel) collapsed behind a single toggle button that opens an overlay panel sliding in from the right and closes via an X, rather than controls occupying space inline on the page ("terlalu memakan tempat"). Confidence: 0.55
- Wants precise, exact values shown in the UI rather than rounded or partial ones — asks for timestamps to include hour, minute, and second ("pastikan jam menit hingga detiknya juga ditampilkan"), not just the date or HH:MM. Confidence: 0.45
- Renames technical/database-style field labels to plain domain terms end users understand ("agar lebih mudah dipahami user") — e.g. "Level 4" → "Desa", "Level 5" → "SLS" — while keeping the underlying DB column names unchanged so no migration is needed. Confidence: 0.6
